# Модель данных

Стадия: **Концепт**. Волна 1.
Описывает, какие сущности есть в системе, какими полями заданы и как к ним обращаются модули.

---

## Принципы

1. **Схема описывается как таблицы**, хотя база пока локальная. Переход на Postgres не должен требовать переосмысления данных — только замены адаптера.
2. **Доступ к данным только через `store`.** Модуль не знает, где лежат записи.
3. **Интерфейс хранилища асинхронный с первого дня.** Локальное хранилище синхронное, но если писать вызовы под него, переход на сеть перепишет каждый модуль. Все методы возвращают промис.
4. **Каждая запись готова к синхронизации:** собственный `uuid`, отметка изменения, мягкое удаление. Без этого слияние двух устройств невозможно — удалённая запись вернётся с другого устройства.
5. **Время хранится в UTC.** Отдельно хранится локальная дата — по ней группируется день.
6. **Числа в базовых единицах:** миллилитры, граммы, секунды. Никаких «полтора литра» в хранилище.

---

## Общие поля

Есть у каждой прикладной таблицы.

| Поле | Тип | Назначение |
|------|-----|-----------|
| `id` | uuid | Генерируется на устройстве. Случайный, чтобы записи с разных устройств не столкнулись |
| `created_at` | timestamptz | Когда запись появилась |
| `updated_at` | timestamptz | Когда изменена. Основа для разрешения конфликтов при слиянии |
| `deleted_at` | timestamptz, null | Мягкое удаление. Запись остаётся как надгробие, иначе удаление не переживёт синхронизацию |

## Таблица `water_intake`

Одна запись — один зафиксированный приём воды.

| Поле | Тип | Правила |
|------|-----|---------|
| `at` | timestamptz | Момент приёма. Обычно совпадает с моментом нажатия |
| `local_date` | date | Локальная дата с учётом границы суток. Нужна для группировки без пересчёта часовых поясов |
| `amount_ml` | integer | Больше нуля, не больше 5000 |
| `source` | text | `tap` — 250 мл, `hold` — литр удержанием, `manual` — введено вручную |
| `note` | text, null | Свободная пометка. Пока не используется, но добавить поле позже дороже, чем сейчас |

```sql
create table water_intake (
  id          uuid primary key,
  at          timestamptz not null,
  local_date  date        not null,
  amount_ml   integer     not null check (amount_ml > 0 and amount_ml <= 5000),
  source      text        not null check (source in ('tap', 'hold', 'manual')),
  note        text,
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now(),
  deleted_at  timestamptz
);

create index water_intake_day_idx on water_intake (local_date);
create index water_intake_at_idx  on water_intake (at desc);
```

## Таблица `water_goal`

Норма — не одно число, а история значений.

**Почему так:** если норма хранится одним числом и меняется с 2 на 3 литра, вся прошлая статистика пересчитывается по новой норме. Март, в котором норма была выполнена, задним числом станет проваленным. Восстановить, какой норма была тогда, будет уже неоткуда. Стоимость сейчас — одна таблица из трёх полей.

| Поле | Тип | Правила |
|------|-----|---------|
| `ml` | integer | От 200 до 10000 |
| `effective_from` | date | С какой даты действует |

```sql
create table water_goal (
  id              uuid primary key,
  ml              integer     not null check (ml between 200 and 10000),
  effective_from  date        not null,
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now(),
  deleted_at      timestamptz
);
```

Норма на дату — последняя запись с `effective_from <= дата`.

## Таблица `settings`

Плоский набор параметров. Значение — JSON, чтобы не плодить колонки под каждую настройку.

```sql
create table settings (
  key         text primary key,
  value       jsonb       not null,
  updated_at  timestamptz not null default now()
);
```

Ключи на текущий момент:

| Ключ | По умолчанию | Смысл |
|------|--------------|-------|
| `day_start_hour` | `0` | Час, с которого начинается новый день. Сейчас полночь; поле оставлено настраиваемым |
| `water.tap_ml` | `250` | Объём одного тапа |
| `water.hold_ml` | `1000` | Объём удержания на секунду |
| `water.soft_after_min` | `72` | Через сколько минут кольцо становится зелёным |
| `water.hard_after_min` | `180` | Через сколько минут кольцо становится красным |

## Таблица `meta`

Служебная, одна строка.

| Поле | Назначение |
|------|-----------|
| `schema_version` | Версия схемы. Растёт при каждом изменении структуры, включает миграцию |
| `device_id` | Идентификатор устройства. Понадобится, чтобы разбирать конфликты при слиянии |

## Интерфейс хранилища

Единственная точка доступа. Все методы асинхронные.

```js
store.list(collection, { from, to, includeDeleted })  // → массив записей
store.get(collection, id)                             // → запись или null
store.put(collection, record)                         // вставка или обновление
store.remove(collection, id)                          // мягкое удаление
store.onChange(collection, handler)                   // подписка на изменения
store.exportAll()                                     // → JSON целиком
store.importAll(json, { mode })                       // замена или слияние
```

**Что делает `put`:** проставляет `id`, если его нет, обновляет `updated_at`, проверяет запись по описанию схемы, пишет, оповещает подписчиков. Модуль не занимается ничем из этого.

**Адаптер один и остаётся местным.** Ранняя запись про «`remoteAdapter` поверх Postgres» отменена: она означала бы, что каждое касание кружка идёт в сеть, и приложение переставало бы работать без связи.

Postgres добавляется сбоку, отдельным слоем синхронизации:

```
модули → store → localAdapter → браузер устройства
                      ↕
                 синхронизация ⇄ Postgres
```

Маршрут перехода описан в `docs/postgres-route.md`. Модули работают с `store` и ни о сети, ни о её отсутствии не знают.

## Раскладка в локальном хранилище

Одна коллекция — один ключ, значение — массив записей в JSON.

```
pr:v1:water_intake
pr:v1:water_goal
pr:v1:settings
pr:v1:meta
```

**Потолок:** объём браузерного хранилища около 5 МБ. Запись о воде занимает примерно 150 байт, при восьми приёмах в день это порядка 450 КБ в год. Воде хватит надолго, тренировкам с подходами — нет.

**Точка переключения:** когда суммарный объём подойдёт к половине лимита, локальный адаптер переводится на IndexedDB. Для модулей это ничего не меняет — интерфейс тот же, вызовы уже асинхронные.

## Контракты с оболочкой

Вынесены в отдельный документ: `docs/contracts.md`. Там описаны срочность для ряда кружков, лента записей и сервис отмены.

Здесь важно одно следствие для данных: **уровень срочности нигде не хранится.** Он вычисляется из последней записи в момент отрисовки.

## Закрытые вопросы

1. **Ночь.** Срочность нарастает как обычно, тихих часов нет. Утренний красный кружок — ожидаемое поведение, а не сбой.
2. **Граница суток.** Полночь. Стакан, выпитый в час ночи, относится к новому дню.
3. **Норма выполнена.** Кружок продолжает напоминать мягко, но до красного не доходит.

---

## Принято по умолчанию

1. Идентификаторы — случайные uuid, генерируются на устройстве.
2. Норма хранится историей, а не одним числом.
3. Удаление мягкое во всех таблицах.
4. Пороги срочности лежат в настройках и меняются без правки кода.
5. Поле `note` заведено заранее и пока не используется.
