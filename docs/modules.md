# Карта модулей

Стадия: **принято, реализуется.** Документ описывает разбиение целиком; отдельные
модули проходят свои стадии независимо. Что уже сделано - в `docs/decisions.md`,
что осталось - в таблице волн ниже.

---

## Принципы разбиения

1. Четыре слоя: **ядро → интерфейс → домены → сквозные**. Зависимости идут только вниз.
2. Домен не обращается к другому домену напрямую — только через ядро.
3. Модуль владеет своими данными и своим экраном. Чужие экраны не рисует.
4. Любой модуль можно вырезать, и приложение продолжает запускаться.

---

## Слой 1. Ядро

### 1.1 `store` — хранилище

- **Задача:** единственная точка чтения и записи данных.
- **Отвечает за:** CRUD коллекций, версию схемы, миграции, экспорт/импорт JSON, резервную копию.
- **Не отвечает за:** смысл данных, доменные правила, интерфейс.
- **Вход:** имя коллекции + объект. **Выход:** данные + событие об изменении.
- **Зависимости:** нет.

### 1.2 `schema` — модель данных

- **Задача:** описать сущности и проверить корректность перед записью.
- **Отвечает за:** поля сущностей, типы, значения по умолчанию, валидацию, `id` и даты.
- **Не отвечает за:** хранение и отображение.
- **Зависимости:** нет. Используется `store` и доменами.

### 1.3 `bus` — события

- **Задача:** развязать модули между собой (публикация/подписка).
- **Отвечает за:** оповещение «данные изменились», «день сменился», «цель достигнута».
- **Не отвечает за:** хранение состояния.
- **Примечание:** на старте избыточен. Вводится, когда появится второй домен.

## Слой 2. Интерфейс

### 2.1 `shell` — каркас приложения

- **Задача:** оболочка, внутри которой живут экраны модулей.
- **Отвечает за:** навигацию (роутинг по hash), шапку, меню разделов, тему светлая/тёмная, точку монтирования экрана.
- **Не отвечает за:** содержимое экранов.

### 2.2 `ui` — набор элементов

- **Задача:** единый визуальный язык.
- **Состав:** кнопка, поле ввода, числовой степпер, селект, чекбокс, карточка, список, модалка, подтверждение, тост, вкладки, пустое состояние, загрузка, ошибка.
- **Правило:** элементы не знают про `store` и про домены. На входе — параметры, на выходе — разметка и события.

### 2.3 `charts` — графики

- **Задача:** визуализация динамики.
- **Состав:** линия, столбцы, кольцо прогресса, тепловая карта по дням.
- **Вход:** массив `{дата, значение}`. **Выход:** SVG.
- **Реализация:** ручной SVG, без библиотек.

## Слой 3. Домены

### 3.1 `water` — вода

- **Задача:** учёт выпитой воды против дневной нормы.
- **Отвечает за:** быстрое добавление порции в одно касание, отмену последней порции, дневную норму, прогресс за день, историю по дням.
- **Не отвечает за:** еду и КБЖУ, напоминания на первом этапе.
- **Экраны:** один — кольцо прогресса, кнопки порций, список сегодняшних записей.
- **Почему отдельно:** экран частых касаний на телефоне, ему нужен быстрый доступ, а не вкладка внутри питания.

### 3.2 `training` — спорт

- **Задача:** планировать и фиксировать тренировки.
- **Отвечает за:** программы, тренировочный день, упражнения в нём, подходы (вес/повторы/время), таймер отдыха, историю по упражнению.
- **Не отвечает за:** справочник упражнений (см. `catalogs`), вес тела и самочувствие (см. `day`), графики (см. `charts`).
- **Экраны:** список тренировок, экран активной тренировки, карточка упражнения.

### 3.3 `nutrition` — питание

- **Задача:** учёт съеденного.
- **Отвечает за:** приёмы пищи за день, порции, расчёт КБЖУ, шаблоны блюд.
- **Не отвечает за:** воду (см. `water`), справочник продуктов (см. `catalogs`), целевые нормы (см. `goals`).
- **Экраны:** день питания, добавление приёма пищи, шаблоны.

### 3.4 `learning` — обучение

- **Задача:** вести темы обучения и учитывать занятия.
- **Отвечает за:** направления/курсы, разбивку на темы, учебные сессии (время, что сделано), заметки, статус освоения.
- **Не отвечает за:** интервальное повторение и карточки — это отдельный модуль второй очереди.
- **Экраны:** список направлений, тема, журнал сессий.

## Слой 4. Сквозные

### 4.1 `catalogs` — справочники

- **Задача:** редактируемые списки, на которые ссылаются домены.
- **Состав:** упражнения, продукты, темы обучения.
- **Отвечает за:** добавление, редактирование, поиск, единицы измерения.
- **Не отвечает за:** записи активности — только эталонные карточки.

### 4.2 `day` — день

- **Задача:** единая точка входа «что было сегодня».
- **Отвечает за:** сводку дня из всех доменов, вес, сон, самочувствие, отметки о выполнении.
- **Не отвечает за:** ввод данных доменов — только показывает и уводит в нужный экран.

### 4.3 `goals` — цели и метрики

- **Задача:** задать целевые показатели и отслеживать отклонение.
- **Отвечает за:** цель по любому числовому показателю (калории, тренировки в неделю, часы обучения), период, текущий прогресс.
- **Не отвечает за:** расчёт самих показателей — берёт готовые у доменов.

### 4.4 `stats` — аналитика

- **Задача:** динамика и сравнение периодов.
- **Отвечает за:** сбор рядов данных из доменов, агрегацию по неделям/месяцам, серии и стрики.
- **Не отвечает за:** отрисовку — отдаёт данные в `charts`.

## Порядок сборки

| Волна | Модули | Результат |
|-------|--------|-----------|
| 0 | Репозиторий, Pages, страница-заглушка | Контур доставки проверен, ярлык на экране iPhone |
| 1 | `store`, `schema`, `ui`, `shell` | Приложение открывается, пустое, но живое |
| 2 | `water` | Первый рабочий сценарий от начала до конца |
| 3 | `catalogs`, `training` | Спорт закрыт, справочники обкатаны |
| 4 | `nutrition`, `learning` | Все направления закрыты |
| 5 | `day`, `charts`, `stats`, `goals` | Появляется общая картина и прогресс |
| 6 | Экспорт, офлайн-режим, полировка | Готово к ежедневному использованию |

Волна 2 — самая важная: маленький модуль воды проверяет, что архитектура ядра рабочая. Дальше домены собираются по его образцу.

## Границы проекта: чего здесь нет

- Нет сервера, аккаунтов, синхронизации между устройствами.
- Нет внешних API (готовых баз продуктов) — только собственный справочник.
- Нет сборщика и npm-зависимостей.
- Нет фреймворков и препроцессоров.
- Нет мультипользовательности.
- Нет напоминаний и уведомлений на первых волнах.

## Принято по умолчанию

Допущения, сделанные при составлении карты. Оспариваются в любой момент.

1. Пользователь один, профиль один.
2. Данные хранятся локально на устройстве, перенос — через экспорт/импорт JSON.
3. Питание считается по КБЖУ, без микроэлементов.
4. Тренировки — силовые и кардио, с фиксацией подходов.
5. Обучение измеряется временем и статусом темы, без тестов и карточек на первом этапе.
6. Интерфейс — одностраничное приложение с навигацией по hash.
7. Верстка проектируется от экрана iPhone, десктоп получает ту же разметку в более широком контейнере.
8. Норма воды задаётся вручную, без расчёта по весу и активности.
