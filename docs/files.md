## Три слоя и правило зависимостей

Зависимости идут только вниз. Нарушение этого правила — повод остановиться, а не обойти.

| Слой | Что можно | Чего нельзя |
|------|-----------|-------------|
| `core` | Знать про данные | Знать про воду, кружки и экраны |
| `modules` | Знать про свою предметную область и обращаться к `core` | Знать про другие темы и про разметку |
| `ui` | Рисовать по переданным данным | Читать хранилище напрямую |
| `app.js` | Связывать всё вместе | Содержать предметную логику |
| `server` | Принимать и отдавать записи | Знать, что такое вода: список таблиц задан явно |

Проверка: если ради новой темы приходится править `ui` или `core` — контракт составлен неверно.

## Что не коммитить

Файлы `preview-*.png` — снимки для переписки. В репозиторий не идут.

## Проверка после раскладки

**Сначала состав файлов.** Из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File tools\check-files.ps1
```

Скрипт сверяет папку со списком и с контрольными суммами. Он отвечает на два вопроса:

- **чего нет** — отсутствующий модуль обрывает загрузку целиком, страница остаётся пустой;
- **что устарело** — файл от прошлой версии на месте, загружается и ломается уже в работе.

Второе опаснее. Отсутствие файла даёт понятный отказ с именем файла, а устаревшая
версия — необъяснимое поведение вроде «нет такой функции», и искать причину
приходится в коде, который на самом деле верен.

Список контрольных сумм пересобирается последним действием захода. Собранный
в середине, он врёт — и врёт убедительно, потому что выглядит как машинная проверка.

**Пересобирает его `stamp.ps1`, он же ставит отпечаток версии:**

```powershell
powershell -ExecutionPolicy Bypass -File tools\stamp.ps1
```

Одна команда вместо двух — потому что оба действия обязаны быть последними,
и разделять их значит однажды выполнить только одно. Скрипт строит список
по дереву, а не по прежнему списку: иначе новый файл в него не попал бы никогда.
Всякое изменение состава он называет вслух, чтобы случайный файл не оказался
в списке молча.

Отпечаток уезжает в `src/version.js` и виден в меню, раздел «Сервер». Он считается
по содержимому всех файлов, а не по хешу коммита: файл с хешем лежал бы внутри
того же коммита, и узнать его до коммита нельзя. Нужен он затем, что GitHub Pages
отдаёт `Cache-Control: max-age=600` — десять минут телефон может исполнять прежнюю
версию, и без этой строки «правка не работает» неотличимо от «правка не доехала».

**Потом запуск:**

```bash
py tools\serve.py
```

Обычный `http.server` отдаёт файлы без указаний о кэшировании, и браузер решает
сам: часть перезапрашивает, часть берёт из памяти и на сервер не ходит вовсе.
Файл на диске свежий, проверка целостности довольна, а в браузере работает старая
версия — и ошибка выглядит как ошибка в коде. `serve.py` запрещает кэширование
и снимает этот класс проблем целиком.

Открыть по очереди: `/` — контур, `/check.html` — ядро, `/app.html` — приложение.

**Если страница всё-таки пустая:** открыть консоль браузера, вкладка Console.
Строка вида `404 ... /src/core/backup.js` называет пропущенный файл прямо.
