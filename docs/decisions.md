# Журнал решений

Фиксируются только решения, которые дорого менять позже.
Формат: дата · решение · причина · что отвергнуто.

## 2026-08-23 · Стек — чистый HTML/CSS/JS

**Решение:** без фреймворков, сборщиков и внешних зависимостей.
**Причина:** проект личный, срок жизни длинный, обслуживание должно быть нулевым. Код, который не зависит от версий npm-пакетов, откроется и через пять лет.
**Отвергнуто:** React — избыточен для одного пользователя и добавляет сборку.

---

## 2026-08-23 · Запуск — локальный сервер плюс GitHub Pages

**Решение:** разработка через `python3 -m http.server`, использование через GitHub Pages с добавлением на главный экран iPhone.
**Причина:** приоритет телефона. ES-модули не работают по `file://`, значит двойной клик по `index.html` отпадает вместе с идеей модульной сборки. Локальная сеть требует включённого компьютера. Pages даёт https, ярлык на экране и офлайн-режим.
**Отвергнуто:** `file://` — ломает модули и ненадёжен для хранилища; только локальный сервер — недоступен с телефона вне дома.

## 2026-08-23 · Репозиторий публичный

**Решение:** публичный репозиторий, GitHub Pages на ветке `main`.
**Причина:** Pages для приватных репозиториев требует платного тарифа. Публикуется только код; личные данные остаются в браузере устройства.
**Следствие:** правило — личные данные не коммитятся никогда, каталоги данных внесены в `.gitignore`.

---

## 2026-08-23 · Хранилище — только на устройстве

**Решение:** данные живут в браузере, перенос между устройствами — экспорт и импорт JSON вручную.
**Причина:** нет сервера, нет аккаунтов, нет чужой инфраструктуры.
**Основной носитель:** iPhone. Компьютер — среда разработки и вторичный доступ.
**Известный риск:** Safari на iOS удаляет данные сайта после примерно семи дней без открытия. Смягчается добавлением на главный экран и регулярным экспортом.
**Отложено:** синхронизация через GitHub API — вернуться к вопросу после волны 3.

## 2026-08-23 · Вода — отдельный модуль

**Решение:** `water` выделен из `nutrition` в самостоятельный модуль и делается первым.
**Причина:** это экран частых касаний, ему нужен быстрый доступ, а не вкладка внутри питания. Как первый модуль он мал, замкнут и прогоняет весь ядерный стек: хранилище, схему, интерфейс, норму и график.
**Порядок:** вода → спорт → остальное.

## 2026-08-23 · Логотип — круглый викингский щит

**Решение:** чёрный фон, круглый щит с четырьмя четвертями по осям, красные и белые попарно напротив друг друга. Обод хромированный, со слабым свечением по контуру. В центре — хромированный умбон. Отрисовка простая, без фактур и теней.
**Причина:** прямой бриф пользователя.
**Исходник:** `assets/icons/logo.svg` — правится он, растры пересобираются из тех же параметров.
**Открыто:** палитра приложения (бирюза и светлая бумага) не согласуется с логотипом. Требует отдельного решения.

## 2026-08-23 · Палитра — чёрный, красный, хром

**Решение:** приложение перекрашено под логотип. Тёмная тема как единственная, светлой нет.
**Роли цвета:**
- красный `#d8323c` — прогресс, активное действие, заполнение;
- хром `#e6eaee` и градиент `--g-chrome` — границы, кольца, выполненные состояния, основной текст;
- янтарь `#e0a32e` — внимание;
- `#ff5a4a` — только поломка и деструктивные действия.

**Правило:** красный не несёт мелкий текст — контраст на чёрном для этого недостаточен. Красный заполняет, обводит и отмечает; читаемое пишется хром-белым или сталью.
**Отвергнуто:** прежняя бирюзовая палитра, собранная до брифа на логотип; светлая тема — она конфликтует с чёрной основой и удваивает работу над каждым экраном.

## 2026-08-23 · Имя репозитория — маскировка

**Решение:** репозиторий называется `test_trash`, имя рабочее и не меняется.
**Причина:** репозиторий публичный. Неприметное имя снижает шанс, что случайный читатель ленты откроет его и станет разбираться.
**Что это защищает:** от просмотра списка репозиториев в профиле и от случайного любопытства.
**Чего не защищает:** от поиска. Страницы GitHub Pages индексируются поисковиками, и заголовок приложения виден.
**Дополнено:** добавлены `robots.txt` с полным запретом обхода и метатег `noindex` в `index.html`.
**Незыблемо:** личные данные в репозиторий не попадают ни при каких условиях. Маскировка имени этого правила не заменяет.
