# Журнал решений

Фиксируются только решения, которые дорого менять позже.
Формат: дата · решение · причина · что отвергнуто.

---

## 2026-08-23 · Стек — чистый HTML/CSS/JS

**Решение:** без фреймворков, сборщиков и внешних зависимостей.
**Причина:** проект личный, срок жизни длинный, обслуживание должно быть нулевым. Код, который не зависит от версий npm-пакетов, откроется и через пять лет.
**Отвергнуто:** React — избыточен для одного пользователя и добавляет сборку.

---

## 2026-08-23 · Запуск — локальный сервер плюс GitHub Pages

**Решение:** разработка через `python3 -m http.server`, использование через GitHub Pages с добавлением на главный экран iPhone.
**Причина:** приоритет телефона. ES-модули не работают по `file://`, значит двойной клик по `index.html` отпадает вместе с идеей модульной сборки. Локальная сеть требует включённого компьютера. Pages даёт https, ярлык на экране и офлайн-режим.
**Отвергнуто:** `file://` — ломает модули и ненадёжен для хранилища; только локальный сервер — недоступен с телефона вне дома.

## 2026-08-23 · Репозиторий публичный

**Решение:** публичный репозиторий, GitHub Pages на ветке `main`.
**Причина:** Pages для приватных репозиториев требует платного тарифа. Публикуется только код; личные данные остаются в браузере устройства.
**Следствие:** правило — личные данные не коммитятся никогда, каталоги данных внесены в `.gitignore`.

## 2026-08-23 · Хранилище — только на устройстве

**Решение:** данные живут в браузере, перенос между устройствами — экспорт и импорт JSON вручную.
**Причина:** нет сервера, нет аккаунтов, нет чужой инфраструктуры.
**Основной носитель:** iPhone. Компьютер — среда разработки и вторичный доступ.
**Известный риск:** Safari на iOS удаляет данные сайта после примерно семи дней без открытия. Смягчается добавлением на главный экран и регулярным экспортом.
**Отложено:** синхронизация через GitHub API — вернуться к вопросу после волны 3.

## 2026-08-23 · Вода — отдельный модуль

**Решение:** `water` выделен из `nutrition` в самостоятельный модуль и делается первым.
**Причина:** это экран частых касаний, ему нужен быстрый доступ, а не вкладка внутри питания. Как первый модуль он мал, замкнут и прогоняет весь ядерный стек: хранилище, схему, интерфейс, норму и график.
**Порядок:** вода → спорт → остальное.

## 2026-08-23 · Палитра — чёрный, красный, хром

**Решение:** приложение перекрашено под логотип. Тёмная тема как единственная, светлой нет.
**Роли цвета:**
- красный `#d8323c` — прогресс, активное действие, заполнение;
- хром `#e6eaee` и градиент `--g-chrome` — границы, кольца, выполненные состояния, основной текст;
- янтарь `#e0a32e` — внимание;
- `#ff5a4a` — только поломка и деструктивные действия.

**Правило:** красный не несёт мелкий текст — контраст на чёрном для этого недостаточен. Красный заполняет, обводит и отмечает; читаемое пишется хром-белым или сталью.
**Отвергнуто:** прежняя бирюзовая палитра, собранная до брифа на логотип; светлая тема — она конфликтует с чёрной основой и удваивает работу над каждым экраном.

## 2026-08-23 · Имя репозитория — маскировка

**Решение:** репозиторий называется `test_trash`, имя рабочее и не меняется.
**Причина:** репозиторий публичный. Неприметное имя снижает шанс, что случайный читатель ленты откроет его и станет разбираться.
**Что это защищает:** от просмотра списка репозиториев в профиле и от случайного любопытства.
**Чего не защищает:** от поиска. Страницы GitHub Pages индексируются поисковиками, и заголовок приложения виден.
**Дополнено:** добавлены `robots.txt` с полным запретом обхода и метатег `noindex` в `index.html`.
**Незыблемо:** личные данные в репозиторий не попадают ни при каких условиях. Маскировка имени этого правила не заменяет.

## 2026-08-23 · Состояние не кодируется одним оттенком

**Что произошло:** на странице проверки все индикаторы выглядели одинаково пустыми. Причина — в палитре нет зелёного, норма обозначена хром-белым, а неизвестное состояние — серым. На экране телефона точка размером 10 пикселей белого от серого не отличается.
**Решение:** состояние различается формой и свечением, а не только цветом. Неизвестно — пустой контур. Любое определённое состояние — залитый круг с подсветкой.
**Правило для модуля `ui`:** ни один статус, порог или результат не обозначается одним лишь оттенком. Цвет — усиление, а не единственный носитель смысла. Рядом всегда есть форма, подпись или значение.

## 2026-08-23 · Хранилище — локально, схема как под Postgres

**Решение:** данные описываются полноценными таблицами, но пишутся в браузер. Доступ через `store` с подменяемым адаптером. Интерфейс асинхронный с первого дня.
**Причина:** вода — тестовый модуль, на нём проверяется архитектура ядра. Проверять одновременно архитектуру и облачную базу с правами доступа означает не понять, что именно сломалось. При этом схема сразу пишется так, чтобы переезд на Postgres не переосмысливал данные.
**Следствие:** каждая запись несёт uuid, отметку изменения и мягкое удаление — без этого слияние устройств невозможно.
**Отвергнуто:** сразу Supabase — добавляет учётные записи, ключи и права доступа в момент, когда ещё не проверено ядро; чистое локальное хранение без задела — обрекает на переписывание модулей.
**Открыто:** подключение `remoteAdapter` — после волны 3.

## 2026-08-23 · Ряд кружков как очередь по срочности

**Решение:** главный экран — ряд кружков в стилистике историй. Выполненное гаснет до серого и уходит в конец ряда, несделанное поднимается к началу. Чем дольше бездействие, тем агрессивнее кольцо.
**Причина:** форма привычна и считывается мгновенно, порядок сам отвечает на вопрос «что делать сейчас».
**Следствие для архитектуры:** каждый модуль обязан отдавать оболочке уровень срочности, вес для сортировки и короткую сводку. Это общий контракт, а не особенность воды.
**Для воды:** серый — только что выпил или норма закрыта; зелёный — больше 72 минут; красный — больше 180 минут. Пороги в настройках.

## 2026-08-23 · Ввод воды — тап и удержание

**Решение:** тап — 250 мл. Удержание секунду — литр. Удержание три секунды — ручной ввод. Во время удержания растёт кольцо заполнения, чтобы жест был виден.
**Причина:** исходные три и десять секунд без обратной связи неотличимы от зависшего экрана, десять секунд утомляют палец.
**Обязательно:** отмена последнего действия. При вводе в одно касание промахи неизбежны.

## 2026-08-23 · Поведение кружка воды во времени

**Ночь:** срочность нарастает во сне на общих основаниях. Тихих часов нет.
**Следствие, принятое сознательно:** после ночи кружок почти всегда красный. Утро начинается с воды.
**Граница суток:** полночь. Выпитое в час ночи относится к новому дню. Настройка `day_start_hour` оставлена, но равна нулю.
**Выполненная норма:** уровень срочности выше мягкого не поднимается. Напоминание остаётся, тревоги нет — пить после нормы полезно, требовать этого нет оснований.
**Отменено:** настройка `quiet_hours` удалена из схемы. Неиспользуемая настройка хуже отсутствующей: её видно, и рано или поздно кто-то на неё понадеется.

## 2026-08-23 · Отмена и лента — общие сервисы, не части воды

**Решение:** таблетка отмены живёт в `ui`, лента недавних записей — в оболочке. Модуль воды не содержит ни того, ни другого.
**Причина:** сделанное внутри воды пришлось бы писать заново для спорта, питания и обучения.
**Следствие:** у оболочки появился второй контракт к модулям — лента записей, рядом с уже существующим контрактом срочности. Описаны в `docs/contracts.md`.
**Проверка контракта:** если ради нового модуля приходится править оболочку, контракт составлен неверно.

## 2026-08-23 · Стопка отмен

**Решение:** действия складываются в стопку. Таблетка показывает вершину и отсчитывает семь секунд. Отмена снимает вершину и показывает следующую запись с новым отсчётом. По истечении семи секунд закрывается вся стопка, а не только вершина.
**Смысл:** стопка жива, пока между действиями проходит меньше семи секунд. Пауза длиннее — сделанное считается принятым.
**Хранение:** стопка только в памяти. Перезапуск приложения её обнуляет, сами записи остаются.
**Отвергнуто:** одна отмена на последнее действие — не спасает при трёх тапах подряд, а это основной способ ввода.

## 2026-08-23 · Двадцать четыре часа — окно показа

**Решение:** лента недавних записей показывает сутки. Данные хранятся бессрочно.
**Причина:** уточнено отдельно, поскольку обратное прочтение сделало бы недельные графики и любую статистику невозможными.
**Разделение:** лента — инструмент исправления ошибок за сегодня. Полная история модуля — на его собственном экране.
**Лента общая для всех модулей**, с переключателем фильтра по модулю.

## 2026-08-23 · Ядро реализовано

**Состав:** `schema.js` — таблицы и проверка записей, `adapter-local.js` — хранение в браузере, `store.js` — единая точка доступа. Отдельно `check.html` — самопроверка из семнадцати сценариев.

**Что закреплено в коде:**
- Схема закрыта: поле, не описанное в схеме, запись не пройдёт. Опечатка в имени поля обнаруживается сразу, а не через месяц по пустому графику.
- Битый JSON в хранилище не проглатывается молча, а поднимает ошибку. Тихая потеря данных хуже явного отказа.
- Слияние выгрузок разрешается по `updated_at`: побеждает более поздняя версия записи.
- Проверка ядра работает в пространстве ключей `pr:test:` и убирает за собой. Настоящие данные не затрагиваются ни при каком исходе.

**Отвергнуто:** синхронный интерфейс хранилища, хотя браузерное хранилище синхронное. Асинхронность с первого дня — цена перехода на Postgres без переписывания модулей.

## 2026-08-23 · Раскладка главного экрана

**Решение:** три зоны — шапка 3–7 %, ряд кружков 12–23 %, остальное под ленту карточек модулей.
**Поправка:** доли страхуются пиксельными минимумами. Шапка не ниже 56 px: три процента высоты iPhone дают около 25 пикселей, а зона уверенного касания — 44. На маленьком экране шапка займёт больше семи процентов, и это правильнее непопадаемой кнопки.

## 2026-08-23 · Два указателя в кружке

**Решение:** кольцо по краю показывает срочность, капля внутри — прогресс дня. Указатели независимы.
**Причина:** это разные вопросы. Можно выпить норму за утро и к вечеру получить красное кольцо при полной капле.
**Процент:** по умолчанию скрыт, проступает на 7 секунд после действия. Срок совпадает с жизнью таблетки отмены — пока видно, что засчиталось, доступна и отмена.

## 2026-08-23 · Жест открытия карточки

**Решение:** удержание три секунды открывает карточку воды. Ручной ввод находится внутри неё.
**Причина:** снимает конфликт жестов. Тап и удержание на секунду заняты вводом, отдельного жеста для входа в модуль не оставалось.
**Следствие:** отдельного всплывающего окна для ручного ввода нет — жест уже привёл на нужный экран.

## 2026-08-23 · Правило вёрстки списков

**Решение:** значение стоит справа от названия только если пара укладывается в одну строку на экране телефона. Не укладывается — значение уходит под название.
**Причина:** обнаружено на странице проверки ядра: названия ушли в три строки, список растянулся вдвое.
**Область действия:** любой список во всех модулях.

## 2026-08-23 · Литр и экран исключают друг друга

**Решение:** отпустил между первой и третьей секундой — записан литр. Дотянул до трёх — литр отменяется, открывается экран воды. Одним жестом получить и запись, и переход нельзя.
**Обратная связь:** на втором круге набранный литр зримо утекает — первое кольцо гаснет по мере заполнения второго. Жест длится три секунды, и всё это время должно быть видно, что произойдёт при отпускании.

## 2026-08-23 · Карточка и экран — разные вещи

**Карточка** — свёрнутый вид модуля в ленте главного экрана. Фон-изображение, поверх статистика, между ними обязательное затемнение: яркость пользовательского снимка предугадать нельзя.
**Экран** — развёрнутый вид, открывается удержанием кружка или тапом по карточке. Двух разных развёрнутых видов у модуля нет.
**Причина разведения названий:** оба назывались карточкой, и в обсуждении это уже путалось.

**Ограничение:** свечение капли и свечение кольца одновременно не включаются. При закрытой норме кольцо держится на мягком уровне, так что конфликта не возникает.

## 2026-08-23 · Кружок воды отрисован

**Состав:** `src/ui/circle.js` — чистая функция, на входе описание состояния, на выходе SVG. Данных не читает, событий не слушает. Витрина всех состояний — `states-water.html`.

**Цвета, добавленные в палитру:**
- `--c-mod-water` `#58b6ee` — цвет модуля воды, живёт в капле и в кольце удержания;
- `--c-urgent-soft` `#35bf6b` — мягкое напоминание в кольце срочности.

Каркас остаётся чёрно-хромовым. Цвет модуля не заходит в кольцо срочности: кольцо говорит на общем для всех модулей языке.

**Заливка по телу капли.** Обнаружено на первой отрисовке: при отсчёте по высоте кружка девяносто процентов выглядели как полная норма — остриё капли слишком узкое. Поверхность жидкости теперь ходит от основания до острия.

**Второй круг удержания** нарисован хромом, а не цветом воды: он означает не воду, а переход. Голубое кольцо при этом гаснет — литр зримо утекает.

**Исправлено попутно:** в `check.html` и `states-water.html` подключение скрипта стояло после закрывающего тега `body`. Браузеры это прощают, но полагаться на снисходительность разбора не стоит.

## 2026-08-23 · Кольцо состояния — зазор и переход цвета

**Решение по образцам из мессенджеров:**
- Между кольцом состояния и подложкой оставлен зазор. Кольцо читается как отдельный указатель, а не как обводка содержимого.
- Кольцо стало тоньше: четыре сотых диаметра вместо пяти.
- Зелёный и красный получили переход цвета: `#3ce07e → #0e9e6a` и `#ff6b4a → #b3121f`. Плоская заливка на чёрном выглядит нарисованной маркером.
- Серый повторяет приглушённый стиль образца: `#303c4a`, без перехода. Он не должен спорить с содержимым.

**Почему серый без градиента.** Переход цвета — способ привлечь внимание. Состояние «сделано недавно» внимания не требует, и выделять его нечем.

**Кольца удержания** переход не получают: они показывают ход жеста, а не состояние. Голубое — набор литра, хромовое — переход на экран.

## 2026-08-23 · Карточка модуля — компоновка «Пост»

**Выбрано:** всё прижато к низу, верх отдан изображению. Два других варианта удалены, а не оставлены про запас.

**Состав сверху вниз:**
1. Эмблема, название, описание карточки, процент справа.
2. График: день или неделя, переключается свайпом. Под графиком — точки-указатели.
3. Крупная цифра, полоса дня, подпись о последнем приёме.

**График белый.** Он лежит поверх изображения, и цвет модуля на произвольном снимке потерялся бы. Цвет модуля остаётся в эмблеме и в полосе прогресса.

**Фон приглушён до 35 %** плюс затемнение сверху. Иначе график нечитаем на светлом снимке, а какой снимок выберет пользователь — неизвестно.

**Шрифт крупных чисел:** `Avenir Next`, далее `Futura` и прочие геометрические из системных. Внешние шрифты не подключаются: они требуют сети при первом запуске и ломают автономность.

## 2026-08-23 · Графики карточки

**Два типа, каждый отключается отдельно:**

## 2026-08-23 · Темы и два порядка на одном экране

**Терминология:** в интерфейсе — **тема**, в коде — модуль. Темы на сейчас: «Питание», «Водный баланс», «Спорт».
У темы два названия: полное для карточки и короткое для подписи под кружком. «Водный баланс» под кружком в 72 пикселя не помещается.

**Два порядка, и они разные:**
- **Лента карточек** — порядок задаёт пользователь перетаскиванием в меню, пункт «Порядок отображения тем». Порядок постоянный.
- **Ряд кружков** — порядок вычисляется по срочности. Что дольше ждёт, то ближе к началу; сделанное уходит в конец.

**Почему не один порядок.** Кружки отвечают на вопрос «чем заняться сейчас», карточки — «мои темы в моём порядке». Подчинить кружки ручному порядку значит лишить их смысла: они перестанут перестраиваться и превратятся в дубль ленты.

## 2026-08-23 · Порядок кружков — по срочности, внутри уровня вручную

**Причина:** просроченное всплывает наверх, но при равной срочности ряд не пляшет. Порядок остаётся узнаваемым, а места тем — предсказуемыми.

## 2026-08-23 · Поправка: Postgres не заменяет местное хранилище

## 2026-08-23 · Postgres на своём сервере

**Зачем:** надёжность хранения и синхронизация между устройствами одновременно. Обмен двусторонний.
**Где:** собственный сервер. Данные не уезжают к стороннему поставщику, доступ к SQL прямой.
**Когда:** после выхода воды в прод. Раньше синхронизировать нечего.

**Обмен — две ручки, а не готовая надстройка над базой.** Готовые решения тянут за собой роли базы и построчные права доступа: механизм мощный и ровно поэтому опасный, ошибка в одном правиле открывает всё. Для одного пользователя нужно `GET /changes?since=` и `POST /changes` — полторы сотни строк, которые целиком помещаются в голове.

**Поля `user_id` не будет.** Пользователь один, разграничивать нечего. Появится второй — добавится миграцией.

**Обслуживание не разовое.** Раз в пару месяцев: обновления безопасности, срок сертификата, проверка того, что резервные копии снимаются и восстанавливаются. Копия, которую ни разу не пробовали восстановить, копией не является.

## 2026-08-23 · Лента недавних записей

**Состав:** `src/ui/recent.js` — лента за сутки по всем темам, с фильтром и удалением. Открывается из меню строкой «Недавние записи».

## 2026-08-25 · Проверка свежести файлов

## 2026-08-25 · Служебные скрипты — без кириллицы

**Что произошло:** `check-files.ps1` не запустился, разбор упал на закрывающей скобке в конце файла.

**Причина не в скобках.** Windows PowerShell читает файлы `.ps1` в системной кодировке, а не в UTF-8. Русский текст превращался в набор символов, среди которых попадались типографские кавычки. PowerShell считает их настоящими кавычками: строка обрывалась посередине, дальше разбор шёл вразнос и падал на первой же скобке, которая теперь оказывалась лишней.

**Решение:** служебные скрипты пишутся только латиницей. Кодировку в этом случае можно не угадывать вовсе.

**Отвергнуто:** сохранять файл с меткой кодировки в начале. Работает, но требует помнить об этом при каждой правке в любом редакторе. Ограничение алфавитом надёжнее договорённости.

**Область действия:** только исполняемые файлы для оболочки. Код приложения, документы и интерфейс остаются на русском — их читает браузер, и он кодировку понимает правильно.

## 2026-08-25 · Локальный сервер запрещает кэширование

**Что произошло:** файлы на диске были верные, проверка целостности показывала полное совпадение, а приложение продолжало падать на методе, который в файле есть. В логе сервера запроса к этому файлу не было вовсе.

**Причина:** обычный `http.server` отдаёт файлы без указаний о кэшировании. Браузер решает сам: часть файлов перезапрашивает, часть берёт из памяти и на сервер не ходит. Такой файл не появляется в логе, на диске он свежий, а в браузере работает версия недельной давности.

**Чем это опасно:** ошибка выглядит как ошибка в коде. Проверка целостности при этом подтверждает, что всё в порядке, — и уводит от настоящей причины.

**Решение:** `tools/serve.py` — тот же простой сервер, но с запретом кэширования. Разработка ведётся через него.

## 2026-08-25 · Обмен с Postgres написан целиком

**Сервер** (`server/`): две ручки поверх Postgres, пропуск по заголовку, сравнение постоянного времени, список таблиц и полей задан в коде. Плюс автозапуск, обратный прокси с сертификатом, резервные копии с проверкой восстановления и установка по шагам.

**Устройство** (`src/core/sync.js`): отправка изменённого после последней отметки, приём чужого, разрешение конфликтов по времени правки. Настройки и состояние — в меню, раздел «Сервер».

**Ключевые решения:**

- **Отметки времени берутся у сервера.** Часы устройства и сервера расходятся, и курсор, посчитанный не там, начнёт терять записи.
- **Курсор отправки двигается по самой поздней отправленной записи**, а не по «сейчас». Иначе правка, сделанная во время запроса, потеряется навсегда.
- **Сначала отдаём, потом забираем.** Свежая местная правка не должна быть затёрта той же записью, пришедшей с сервера в старой версии.
- **Приём не трогает `updated_at`.** Время правки принадлежит тому, кто её сделал; иначе каждая сторона будет считать свою версию новее и обмен зациклится.
- **Негодная запись отбрасывается поштучно**, вся пачка при этом принимается. Одна испорченная строка не должна останавливать обмен.
- **Пропуск и адрес хранятся в `sync_state`** и на сервер не уезжают: они привязаны к устройству.
- **Обмен молчит.** Неудача — обычное дело, в метро связи нет. Ничего поверх экрана не показывается, состояние видно в меню.

**Проверено на поддельном сервере:** отправка трёх записей, отсутствие повторной отправки, приём чужой записи, обновление экрана. Проверок ядра стало двадцать четыре.

**Не проверено и проверяется только на настоящем сервере:** сертификат, список разрешённых источников, поведение при обрыве посреди пачки.

## 2026-08-25 · Приложение — личное дело, а не трекер

**Формулировка задумки:** человек ведёт дело сам с собой. Трекер отвечает на вопрос «сколько», личное дело — «держу ли я слово». Планировщик, тренер и журнал дисциплины в одном.

**Незыблемые правила устройства, принятые сразу:**

1. **Всё восстановимо.** Нет показателей, которые нельзя выправить за разумный срок.
2. **Объявленный пропуск — не срыв.** Сказать заранее «сегодня пропускаю» честнее, чем промолчать, и приложение поощряет именно это.
3. **Оценка всегда с трендом**, никогда голым числом. Число без направления демотивирует.
4. **Не больше одного тревожного сигнала на экране за раз.** Три красных кружка одновременно читаются как «всё пропало».
5. **Никаких сравнений ни с кем.** Только с собой прежним.

**Причина этих правил.** Приложение для человека с трудностями самоконтроля очень легко превращается в машину вины, и тогда оно работает против собственной цели. Признаки известны: много красного, обнуляющиеся серии, показатели без пути наверх.

## 2026-08-25 · Цель и бюджет пропусков

**Название:** длительное обязательство перед собой называется **целью**.

**Счёт — бюджет пропусков, не серия.** Решено картбланшем.

Серия, которая обнуляется, наказывает не за срыв, а за то, что человек начал: чем длиннее была серия, тем больнее потеря и тем меньше желания начинать заново. Бюджет устроен иначе — девяносто дней, девять пропусков в запасе, пропуск тратит запас, но не отменяет пройденного. После срыва остаётся смысл продолжать, а именно это определяет исход.

**Отвергнуто:** обнуляемая серия в любом виде, включая «на выбор». Наличие такого режима в настройках — приглашение выбрать вредное.

## 2026-08-25 · Оценки

**Надёжность слова.** После невыполненного дня приложение предлагает дать обещание на завтра и назавтра проверяет. **Отказ дать обещание показатель не портит — портит только нарушенное обещание.** Иначе система толкает врать себе, а заводится она ради обратного.

**Восстановление.** Средняя длина провала: сорвался и вернулся назавтра — единица, пропал на две недели — четырнадцать. Для человека с трудностями самоконтроля это главная метрика: безупречных не бывает, доходят живучие.

**Постоянство.** Не сколько, а насколько ровно. Дневная норма воды, выпитая залпом в одиннадцать вечера, формально успех, по сути нет.

**Индекс дисциплины.** Доля выполненного за скользящие двадцать восемь дней. Окно скользящее намеренно: яма не вечная, неделя работы вытягивает.

## 2026-08-25 · Сценарий — общая форма для таймеров и планировщика

**Решение:** секундомер, таймер, интервальный таймер и планировщик дня — одна сущность с разными настройками. Цепочка шагов с длительностями.

- Один шаг без повторов — таймер.
- Два шага с повторами — интервальный.
- Много именованных шагов — план дня.
- Без длительности — секундомер.

**Шаг привязывается к теме.** Отработал шаг «чтение, двадцать минут» — двадцать минут записались в тему сами. Планировщик перестаёт быть отдельной игрушкой и становится способом ввода.

**Экран во время сценария не гаснет:** Safari 18.4 добавил удержание экрана.

## 2026-08-25 · Внутренняя валюта

**Принято с изменениями.** Валюта соединяет сильные области со слабыми и даёт ход после срыва. Это ложится на правило «всё восстановимо»: вместо «ты провалился» - «ты можешь это выправить, и вот чем».

**Четыре правила, без которых механика вредна:**

1. **Начисление только за завершённую цель**, не за дни и не за отдельные выполнения. Иначе появляется фарм: заводишь пять простых целей, копишь и покупаешь пропуски для той единственной, которую на самом деле избегаешь. Система начинает вознаграждать избегание.
2. **Тратить можно только на уже случившийся пропуск**, задним числом, и не старше трёх дней. Не «куплю запас», а «выкуплю вчерашний день». Купленный впрок запас - это разрешение пропустить.
3. **Цена растёт внутри цели.** Первый выкуп дёшев, второй дороже. Злоупотребление ограничивается само, без запретов.
4. **Валюта не копится вечно.** Потолок или сгорание - иначе за год накопится на что угодно, и цели перестанут что-либо значить.

**Общий риск, который эти правила снимают:** внешняя награда вытесняет внутреннюю причину. Человек начинает оптимизировать очки вместо поведения - самый частый способ, которым игровые механики убивают то, что должны поддержать.

**Название уточнено позже:** не «щиты», а «кредит доверия». Запись от 25 августа ниже.

## 2026-08-25 · Вкладка «Сегодня»

Три раздела: **Ждут**, **Сделано**, **Цели**.

- Порядок в разделе «Ждут» — по срочности, как в ряду кружков.
- Сделанное не исчезает, а гаснет и уходит вниз: важно видеть, что день не пустой.
- В строке — кружок, название, сводка и кнопка быстрого ввода: «+250», «+10», «Таймер», «Оценить». Действие зависит от вида темы.
- Значение уходит под название, а не встаёт справа: пара в одну строку на телефоне разъезжается.
- У целей видно день, запас пропусков и остаток щитов. Когда запас на исходе, появляется подсказка про выкуп — а не упрёк.
- Внизу «Сегодня пропускаю…» с объяснением: объявленный пропуск тратит запас, но срывом не считается.

**Пункт «Сегодня» из меню убирается:** вкладка его заменяет, два входа в одно место не нужны.

## 2026-08-25 · Валюта - кредит доверия, а не щиты

**Предложение пользователя:** назвать валюту доверием. Потратить доверие, накопить, сгорает.

**Принято с поправкой, и поправка принципиальная.**

Мы условились: приложение не машина вины. Разница между «потратил щит» и «потратил доверие» огромна. Первое - расход ресурса. Второе - утверждение о том, кто ты есть. «Сгорело доверие» звучит как приговор себе и бьёт ровно в то место, из-за которого человек и пришёл.

**Правило:** ресурс, который тратится, должен быть внешним по отношению к личности. Иначе каждая трата превращается в самообвинение.

**Решение:** валюта называется **кредитом доверия**, в интерфейсе коротко «кредит». Это готовое русское выражение, означающее аванс, выданный заранее. Взять кредит на пропущенный день - заём у себя, а не потеря себя. Метафора пользователя сохранена целиком, обвинение убрано.

**Слово «доверие» отдано метрике надёжности слова:** «Доверие к себе - 82%». Там оно работает без риска, потому что это измерение, а не изъятие.

**Оформление:** кредит показан как ценность - тёплый цвет, знак щита, крупная цифра. Не как строка отчёта.

## 2026-08-25 · Против рутинного вида

**Задача:** приложение не должно выглядеть анкетой. Основной пользователь - человек, которому и так тяжело начать; монотонная форма из двадцати полей отталкивает раньше, чем он дойдёт до первой темы.

**Правила текста:** длинное тире в интерфейсе не используется, только обычный дефис. Многоточие в кнопках тоже убрано.

## 2026-09-07 · Дизайн лёг в репозиторий

## 2026-09-07 · Имена файлов - латиницей

**Что произошло:** пакеты дизайна пришли с русскими именами файлов. При сборке списка контрольных сумм скрипт проверки обнулился: запись в ASCII-файл упала на кириллице, но файл к этому моменту уже был открыт на запись и обрезан в ноль байт.

**Два вывода:**

1. **Имена файлов в репозитории - только латиницей.** Содержимое остаётся русским. Причин три: список сумм в `check-files.ps1` обязан быть ASCII, при упаковке в архив русские имена уже один раз приезжали покорёженными, и путь с кириллицей ломается в части инструментов молча.
2. **Запись файла идёт через временный файл с переименованием.** Прямая запись при ошибке кодировки оставляет исходник пустым - потеря без предупреждения.

## 2026-09-07 · Разработка переезжает в Claude Code

**Причина:** передача файлов через переписку стоила нескольких заходов - пропавший `backup.js`, устаревший `store.js`, кэш браузера, обнулившийся скрипт сумм. Claude Code работает прямо в папке репозитория: правит файлы, запускает проверки, делает коммиты.

**Разделение труда:** обсуждение замысла, спорные решения и разбор ошибок остаются в переписке; раскладка файлов, прогон проверок и коммиты уходят в Claude Code.

**Что это подтвердило сразу.** Первый же прогон `check-files.ps1` из Claude Code нашёл три расхождения, которые в переписке не были видны:

1. Тринадцати снимков дизайна нет на диске, хотя журнал утверждал обратное.
2. `docs/files.md` не перечислял четыре файла интерфейса, появившихся за последние заходы, и обещал двадцать проверок вместо двадцати четырёх.
3. Шапка `docs/modules.md` говорила «реализация не начинается», хотя реализация шла месяц.

**Правило, которое из этого следует:** документ, объявляющий себя полным описанием, обязан проверяться машиной. `files.md` заявляет полное дерево - значит расхождение с деревом должно быть ошибкой, а не наблюдением.

## 2026-09-07 · Список сумм снова собрался не последним

**Что произошло:** `docs/decisions.md` и `README.md` числятся устаревшими, хотя правились осознанно. Причина та же, что записана 25 августа: список контрольных сумм собран до последней правки этих файлов.

**Почему повторилось:** правило было записано, но не подкреплено ничем машинным. Пересборка списка выполнялась вручную и оказывалась то последней, то предпоследней.

**Решение:** пересборку списка выполняет Claude Code как последнее действие захода, вместе с коммитом. Правило, которое можно забыть, рано или поздно забывают.

## 2026-09-07 · Журнал решений был повреждён при записи

**Что произошло:** файл оборвался ровно на 65536-м байте - на середине символа. Запись про внутреннюю валюту потеряла четыре правила из пяти абзацев, а разбор файла как текста падал с ошибкой кодировки.

**Причина:** дописывание больших блоков в файл через оболочку не гарантирует целостность на границе 64 килобайт. Ошибки при этом не возникает - файл просто обрывается.

**Чем это опасно:** потеря молчаливая. Журнал открывался, читался, содержал почти всё - недостачу было видно только по смыслу.

**Исправлено:** утраченный кусок восстановлен по переписке. Правило на будущее: после дописывания в документ файл перечитывается целиком и проверяется, что последний добавленный заголовок на месте, а разбор проходит без ошибок.

## 2026-09-07 · Точка передачи

**Зачем:** переписка упирается в предел длины, а знание из неё в файлах есть не всё. Появился `docs/handoff.md` - документ, который заменяет чат целиком.

**Что в нём есть сверх остальных документов:** где проект находится прямо сейчас, разделение труда между перепиской, Claude Code и дизайн-чатом, список граблей с объяснением каждой, открытые вопросы и план по заходам.

**Самая ценная часть - грабли.** Каждая строка там стоила захода или больше: пропущенный файл обрывает загрузку, устаревший ломается молча, браузер кэширует, PowerShell читает скрипт в чужой кодировке, дописывание обрывается на 64 килобайтах, `display` перебивает `hidden`, у дуги радиус не меньше половины хорды. Без этого списка новый чат наступит на них заново.

**Правило:** `handoff.md` читается первым при любом переезде. Ссылка на него добавлена в `CLAUDE.md`.
